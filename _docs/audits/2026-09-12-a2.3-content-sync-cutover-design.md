# A2.3 implementation design (working notes)

Issue: AISL #1617 / plan A2.3. Branch `a2.3-content-sync`, pin v0.3.5 (done).

## Architecture

Package engine (`community_base.content_sync` v0.3.5) becomes the only sync engine.
Site keeps: content models, parsers (moved), media semantics, history adapters.

Parser protocol: `discover(checkout, source) -> [SourceItem]`,
`upsert(item, source, media) -> obj|UpsertResult`, `soft_delete_missing(seen_keys, source)`.
Orchestration calls per parser: discover -> list; upsert each item (duplicate keys raise);
soft_delete_missing(seen). One exception per parser = one bounded error entry
`{"content_type": ..., "error": ...}` in package SyncLog.errors; family's remaining
items are skipped, other families continue. No transaction around parser loop.

### Checkout adapter (`content/sync_parsers/checkout_view.py`)

Mirrors the deleted `integrations/services/github_sync/checkout.py` helper surface on top of
package `ImmutableCheckout`:
- thread-local active view; `checkout_scope(root)` / `activate_view(checkout, source)` ctx.
- view.root = synthetic abs prefix (e.g. `/checkout`); dispatchers keep building
  `os.path.join(repo_dir, rel)`; `relative()` strips the prefix.
- dirs derived from package `checkout.files()` manifest; reads via `checkout.read_bytes(rel)`
  (manifest-validated). `kind`: file/dir/None. walk yields (absroot, dirs, files) triples.
- view exposes: relative, authored_relative, authored_image_relative, walk, listdir, kind,
  snapshot(path, max_bytes), text(path, encoding), files().
- helpers: checkout_read_bytes/read_text/walk/listdir/scandir/kind/is_file/is_dir/exists,
  raise_if_checkout_error, active_checkout.
- `ContentCheckoutError` moves here (same ctor `(rel_path, kind, step)`, `.as_error()`).
- package `CheckoutError` from reads -> site `ContentCheckoutError(rel, kind, 'filesystem_boundary')`.

### Family parsers (`content/sync_parsers/`)

Move `dispatchers/*` here, restructure each into:
- `iter_items(view_ctx)` — enumerate+parse files -> (key, payload) pairs. Keys = rel_path,
  or `rel#i` for multi-entry manifests. Parse errors become error payloads (not raises).
- `process_item(payload)` — old per-file body, returns ('created'|'updated'|'unchanged', obj),
  accumulates per-file errors into run sink, tracks seen/failed semantic ids for cleanup.
- `cleanup()` — old dispatcher tail (soft delete by source_repo, excluding seen+failed).
Generic `FamilyParser` implements package protocol over those three; per-family errors
accumulate and are raised ONCE as `FamilyPartialError` at the END of soft_delete_missing
(after cleanup ran). Deleted count under partial syncs is embedded in the error text
(package drops it from counts when soft_delete raises). On clean syncs counts identical.

Registration order in `content/apps.py` ready() = old pipeline order:
courses, workshops, articles, projects, events, instructors, curated_links, downloads,
marketing_pages, interview_questions, tiers. (tiers was a pre-step; now a parser.)

Run state keyed by id(package_checkout): classification cache (moved RepoFileClassifier),
cross-workshop lookup, per-family seen/failed/errors sinks, known_images (manifest scan).

### Error/history compatibility

Site wrapper `integrations/services/content_sync/runner.py`: `run_sync(source, ...)`
calls package `sync_content_source`, then merges structured family errors from the sink
into `log.errors` (as legacy `{'file','error',...}` dicts), flips success->partial, saves.
ALL site entry points call run_sync; package-native paths (webhook/studio/api/durable
handler) call package directly and show the bounded package error. Document in PR.

### Wiring (step 3)

- INSTALLED_APPS: `community_base.content_sync` after `community_base.mail`.
- Webhook: `api/webhooks/github` + `content-sync/github/webhook/` both -> package view.
  Old integrations github_webhook view deleted.
- `sync_content`: delegates to package orchestration via runner; `--from-disk` implies
  force (dev flow works with disabled/missing-secret sources); `--source SLUG`, `--force`.
- `seed_content_sources`: upserts package ContentSource rows; declarations (slug/repo/
  is_private/max_files) + secrets/history from legacy integrations.ContentSource rows by
  repo_name; missing secret -> is_enabled=False + actionable message (no secret printed).
- Studio: mount package studio_urls under /studio/; old /studio/sync/ views become
  adapters reading package models + queuing via package queue (no second engine).
- API: keep /api/sync/sources, /api/sync/history (compat shapes) reading package rows;
  package registry routes appear under /api/v1/ (site already mounts cb api registry — verify).
- Queue: `content_sync_queue.enqueue_content_sync` -> package `queue_source_sync`
  (dispatcher after_commit). Old django-q task string
  `integrations.services.github.sync_content_source`: `integrations/services/github.py`
  facade kept, `sync_content_source` delegates to package orchestration (translates
  persisted task strings), rest re-exported from new homes or removed with import updates.
- Media: parsers receive package media store; `media.upload(checkout_view, rel, source)`
  per image. Site `CONTENT_SYNC_MEDIA_BACKEND` mapping: site S3-disabled/test-mode -> 'null',
  else 's3' with bucket/public-url settings mapped via config shim. NullMediaResult.url ==
  authored path -> no rewrite (preserves null behavior).
- lifecycle.py/watch_content/scheduled jobs: re-point to package queue/rows.
- Data migration P6 (integrations migration): copy ContentSource (preserve UUIDs,
  slug=derived from repo short name w/ sorted-UUID collision suffix, is_enabled=bool(secret),
  cb_slug written back to legacy row), SyncLog (preserve ids/counts/errors/commit/batch;
  tiers_synced/tiers_count -> warnings JSON `{"asl_compat": {...}}`), github WebhookLog rows
  (payload as-is + namespaced Calendly extension keys; legacy dedup key preserved).
  Timestamps restored via queryset.update after create (auto_now_add). Idempotent by PK;
  never deletes legacy rows.

## Hazards

- `/data/agents/...` worktrees shared with concurrent agents: verify state before gates.
- `update` field collisions: package ContentSource.clean() REQUIRES nonblank secret —
  seed/migration must skip full_clean for blank-secret rows (set is_enabled=False instead)
  — actually package clean() raises on blank; use queryset.update or save without clean.
- Package orchestration sets last_synced_commit only on error-free success.
- dispatchers import `integrations.services.github_sync.*` — update all to new homes.
- `content/utils/includes.py` expand_content_includes(repo_dir=...) reads repo files? check
  — it receives repo_dir/base_dir; may use checkout helpers already (used in recap render).
