# Fully retire inline-register.js on workshop detail pages

Status: pending
Tags: `frontend`, `cleanup`
Depends on: None
Blocks: —

## Background

Follow-up from the signup-actions unification (commit `82de486a`), which retired the inline register form on gated surfaces and moved every free-with-sign-in surface onto `templates/accounts/includes/_signup_actions.html`.

`templates/content/workshop_detail.html` (lines 231-238, inside `{% block extra_scripts %}`) still emits, for an anonymous visitor on the pages paywall:

```django
{% if pages_signup_cta_url and not user.is_authenticated %}
<script src="/static/js/accounts/auth-helpers.js"></script>
{{ next_url|json_script:"auth-next-url" }}
<script src="/static/js/accounts/inline-register.js"></script>
{% endif %}
```

Grooming finding (verified against the code):

- The workshop pages paywall now renders `templates/content/_gated_access_card.html`, whose free branch includes `_signup_actions.html` — OAuth buttons + a plain "Create a free account" link + a "Sign in" link. There is NO `id="register-form"` and no `_inline_register_card.html` on this surface anymore.
- `inline-register.js` binds `handleRegister` to `id="register-form"` and toggles for `data-testid="inline-register-oauth-toggle"` / `inline-register-email-toggle`. None of those elements exist on `workshop_detail.html` now, so the script (and its `auth-next-url` / `auth-helpers.js` payload) is dead on this page.
- `auth-helpers.js` on this surface only exists to support `inline-register.js`; `_signup_actions.html` does not depend on it. So the whole `{% if pages_signup_cta_url ... %}` block can be removed.
- `templates/accounts/includes/_inline_register_card.html` has ZERO includers (grep confirmed) — it is already orphaned. It internally loads `inline-register.js`.
- IMPORTANT — leave the standalone register page alone: `templates/accounts/register.html` still uses `_register_form.html`, which has `<form id="register-form" onsubmit="return handleRegister(event)">` and `id="register-email"` etc. So `inline-register.js`, `auth-helpers.js`, and the `auth-next-url` payload on `register.html` are LIVE and required. Do not touch `register.html` or `inline-register.js` behavior.

## Scope

1. In `templates/content/workshop_detail.html`, remove the dead anonymous-paywall script block: the `{% if pages_signup_cta_url and not user.is_authenticated %}` wrapper and its three lines (`auth-helpers.js`, `auth-next-url` `json_script`, `inline-register.js`), plus the `{% comment %}` above it that references "issue #652: inline register card". Leave the rest of `{% block extra_scripts %}` (e.g. the mermaid script include) intact.

2. Update the now-inverted test in `content/tests/test_workshops_public.py`:
   - `test_anonymous_pages_paywall_loads_inline_register_js` (around line 2480) currently asserts the JS IS loaded. Invert it to assert the workshop pages paywall does NOT load `/static/js/accounts/inline-register.js` and does NOT emit `auth-next-url`, while still keeping the Django-comment-leak guard (`assertNotContains(response, '{# ')`). Rename it to reflect the new expectation (e.g. `test_anonymous_pages_paywall_no_inline_register_js`).
   - Verify the sibling tests still pass: `test_anonymous_pages_paywall_shows_signup_actions` (asserts `signup-actions`, `teaser-signup-cta`, `teaser-signin-cta`, no inline card) and `test_anonymous_pages_paywall_uses_expanded_variant_not_compact` (asserts `Sign up with Google` is visible, no oauth-toggle). Neither depends on the JS tag, so they should stay green unchanged.

3. Delete the orphaned partial `templates/accounts/includes/_inline_register_card.html` after re-confirming zero includers via grep (`grep -rn "_inline_register_card" templates/`). If any referencer is found during implementation, do NOT delete — report it instead. If a test references `inline-register-card` only via `assertNotContains` (e.g. lines 1516, 2472, 2503), those stay valid and need no change.

4. Do NOT modify `templates/accounts/register.html`, `templates/accounts/includes/_register_form.html`, `static/js/accounts/inline-register.js`, or `static/js/accounts/auth-helpers.js` — they remain live for the standalone register page.

No user-facing behavior change: the anonymous workshop pages paywall already renders OAuth buttons + "Create a free account" + "Sign in" via `_signup_actions.html`, none of which needs `inline-register.js`. No model/view/URL/API surface is involved, so no API acceptance criteria apply.
