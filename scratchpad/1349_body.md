## Summary of investigation

Both failing tests in `content/tests/test_catalog_tag_presentation_1228.py` are stale. The catalog templates are correct and match the documented design-system contract. The break was introduced by commit `14cef639` ("Render the /blog tag filter", Closes #1319), which added the page-level topic filter-pill row to `blog_list.html` after the #1228 tests were written. The #1228 tests predate that row and do not distinguish a page-level filter pill from a card tag chip, so they now grab the wrong element / assert whole-page absence of a tag that the new filter row legitimately renders.

Per-failure verdict (both point at the test, not the template):

| Failure | Root cause | Verdict | Fix target |
|---|---|---|---|
| `test_clickable_chips_use_exact_classes_and_native_destinations` (path=`/blog`) | Test finds the first `agents-1228` anchor to `/blog?tag=agents-1228`. Two now exist: the new 44px page-level filter pill (rendered first) and the card tag chip. The test only applies its `CLICKABLE_CHIP_CLASSES` filter on `/downloads`, so on `/blog` it grabs the filter pill and asserts it should be a small pill. | Intentional design change (filter pills are `min-h-[44px]` per the Tap Targets table). Update the stale test. | `content/tests/test_catalog_tag_presentation_1228.py` |
| `test_overflow_chips_are_static_accessible_and_keep_three_tag_cap` (path=`/blog`) | The article's 4th tag `production-1228` is correctly capped out of the card (card slices `:3` + `+1` static span) but now appears as a page-level filter pill. The test asserts `>production-1228<` is absent from the whole page, exempting only `/downloads` and `/resources`. `/blog` now has the same filter row and needs the same treatment. | Intentional design change (`/blog` gained the filter row). Design-system contract this matches (`_docs/design-system.md`):
- Clickable tag chip and static tag chip: no `min-h-[44px]` (small pill, `text-xs`, `px-2.5 py-0.5`).
- Page-level filter pills and view toggles: apply `min-h-[44px]` (Tap Targets decision table).
- `blog_list.html` filter row (lines 30-53) uses the 44px filter-pill base; card chips (lines 120-127) use the small-pill base. Both are correct.

Conclusion: this is a test-only fix. Do NOT change any template.

## Scope

Update `content/tests/test_catalog_tag_presentation_1228.py` so the two `visual_regression`-tagged tests assert the current, intended contract, and scope their assertions to the correct element (card tag chip vs page-level filter pill).

### `test_clickable_chips_use_exact_classes_and_native_destinations`
- The intent of this test is the card tag chip (the small clickable pill), not the page-level filter pill.
- Make the element selection scope to the card chip on every path, not only `/downloads`. The card chip is uniquely identified by `class == CLICKABLE_CHIP_CLASSES`; the filter pill uses the `min-h-[44px]` base. Apply the `CLICKABLE_CHIP_CLASSES` filter to the `next(...)` selection for all cases (remove the `/downloads`-only special case) so the assertion always lands on the card chip.
- Keep the existing assertions unchanged: `chip['attrs'].get('class') == CLICKABLE_CHIP_CLASSES`, `assertNotIn('min-h-[44px]', ...)`, and the native `href` destination. These continue to guard the card-chip contract.
- Do not relax the `href` expectations.

### `test_overflow_chips_are_static_accessible_and_keep_three_tag_cap`
- Keep the existing assertions that the overflow indicator is a `span` with `STATIC_CHIP_CLASSES` and text `+N` for every path.
- Replace the whole-page `assertNotIn('>{hidden_tag}<', ...)` cap check with a card-scoped check that survives the presence of a page-level filter row. The 4th card tag must not be rendered as a card tag chip. Concretely: assert no element whose `class` is `CLICKABLE_CHIP_CLASSES` (clickable card chip) or `STATIC_CHIP_CLASSES` (static card chip) has text equal to the hidden tag. This keeps the 3-tag cap genuinely tested on `/blog`, `/downloads`, and `/resources` while tolerating the legitimate filter-pill occurrence.
- Remove the now-obsolete `/downloads`/`/resources` exemption comment and branch, since the card-scoped assertion applies uniformly and no longer needs a whole-page exemption.

### Out of scope
- No template changes. `blog_list.html`, `downloads_list.html`, `collection_list.html`, and the shared card-chip markup already render the correct classes and cap behavior.
- No refactor of the inlined chip classes into a shared partial. `design-system.md` documents the class strings, and no indexed partial owner exists for catalog tag chips today; extracting one is a separate concern, not required to make this contract green.
- Do NOT build the CI gate for `visual_regression` Django tests here (see the CI-gap section below).

### API surface
- Not applicable. This is a rendering-contract test fix with no operator-managed data and no new endpoints.

Then: The hidden fourth topic is not shown as a card chip, even though it may still appear in the page-level "Filter by topic" row as a legitimate filter option
