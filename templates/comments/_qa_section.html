{% comment %} Shared comments thread partial. Used by the course unit Q&A surface, the workshop tutorial Q&A surface, and the personal plan comments surface (issue #499). The plan surface customizes the section heading and composer copy via template parameters; the JavaScript IIFE in ``comments/_qa_script.html`` reads ``data-content-id`` on the wrapper and is identical across surfaces. Parameters: - ``content_id`` (required): UUID matching the content's ``content_id`` / ``Plan.comment_content_id`` field. - ``user_authenticated`` (required): boolean truth value of ``request.user.is_authenticated``. - ``section_heading`` (optional, default "Questions & Answers"): the heading text rendered above the thread. - ``composer_placeholder`` (optional, default "Ask a question about this lesson..."): placeholder text for the new-comment textarea. - ``composer_button_label`` (optional, default "Post Question"): label for the submit button. - ``composer_signin_prompt`` (optional, default "to ask questions, track your progress, and get access to other workshops"): trailing copy after the primary "Sign up" anchor in the anonymous branch. A secondary "Already have an account? Sign in" link is always rendered after the prompt, pointing at ``/accounts/login/?next=`` with the current path. - ``composer_disabled`` (optional, default False): when True the authenticated branch hides the textarea and renders a "discussion not available" notice instead. Used by private-plan owner pages where comments are visible but only staff can write. - ``composer_disabled_reason`` (optional): the text shown in the disabled notice. Defaults to a generic message. - ``instance_id`` (optional): a unique suffix appended to every element id so several threads can coexist on one page (the Book Club chapter page, issue #1365, renders one thread per member note). When omitted the bare ids (``qa-section``, ``qa-new-question``, …) are used exactly as before, keeping single-thread pages unchanged. The ``comments/_qa_script.html`` IIFE wires every ``.qa-thread`` on the page by class, so it is id-suffix agnostic and multi-instance safe. - ``section_class`` (optional, default "mt-12 mb-12"): vertical rhythm on the thread wrapper. The Book Club note card (#1365) passes a tighter "mt-6 mb-0" so the embedded thread fits inside a ``p-6`` card. - ``heading_class`` (optional, default "text-xl"): heading size. The note card passes "text-base" so the thread heading does not dominate the card. Both default to the exact prior values so course / workshop / plan pages render byte-identically. {% endcomment %}
