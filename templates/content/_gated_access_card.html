{% load access_tags %} {% comment %} Canonical gated-content card. This is the ONE partial every paid / tier-gated / free-with-sign-in content block renders (issue #1335). The deprecated ``templates/includes/content_gated.html`` was deleted; all banner copy now comes from ``content.access.build_gating_context`` (or the workshop per-level helpers, which share the same copy builder). Access decisions stay in the views/models; this partial only standardizes the visible hierarchy. Layout: a two-zone "value manifest" card — a clean icon badge on the left, and on the right the requirement pill, heading, description, an optional list of what unlocking includes (``gated_value_items``), the action CTA, the current-access line, and the sign-up / sign-in companions. Expected context: gated_card_testid, gated_icon, gated_heading, gated_description, required_tier_name, current_user_state, gated_value_items, gated_extra_partial, gated_cta_url, gated_cta_label, gated_cta_testid, signup_cta_url, signup_cta_label, signup_cta_testid, signin_cta_url, signin_cta_label, signin_cta_testid, signup_inline ``required_tier_name`` carries the bare tier name (Basic / Main / Premium) and the ``tier_public_label`` filter renders the public label so the pill reads "Basic or above required" / "Main or above required" / "Premium required". The template never branches on tier name; the mapping lives in ``content.access``. When it is empty the gate is free-with-sign-in and a "Free with an account" chip renders instead. ``gated_value_items`` is an optional list of ``{icon, label}`` describing what access unlocks (e.g. workshop overview / page list / tutorial). Absent on surfaces that do not supply it. Issue #652: when ``signup_inline=True`` and the visitor is anonymous, the "Create free account" link is replaced by the inline register card. The parent template/view loads the inline-register JS in extra_scripts. {% endcomment %}
